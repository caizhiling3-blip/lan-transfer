# 测试指南

阶段 3 已加入 Vitest，在 Node 环境测试 shared 协议、错误码和 IPC 类型契约。

每个阶段至少执行：

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

当前单元测试覆盖所有已定义 WebSocket 消息、UUID 与数值边界、UTF-8 文字大小、文件限制、错误码文案完整性和 IPC channel 唯一性。

阶段 4 额外覆盖安全窗口选项、IPC schema 完整性、外链 scheme、连接参数、剪贴板大小、重复选择 token、设置 patch 以及主窗口/main frame 来源校验。

Electron 冒烟测试应确认应用窗口可启动且开发终端没有 preload、CSP 或未处理异常。导航、新窗口和具体 IPC 行为将在拥有对应 UI 后继续补充集成测试。

网络和文件功能实现后补充双机手动测试矩阵。

## 阶段 5

自动化集成测试使用回环地址和系统分配的随机端口，覆盖：

- 健康检查、未知路由和安全响应头；
- `/v1/ws` Upgrade、错误路径和阶段 5 的 1013 关闭；
- 拒绝携带浏览器 Origin 的跨站 WebSocket Upgrade；
- 停止服务后释放端口；
- `EADDRINUSE` 映射、重启、状态事件和运行时错误；
- 重叠 start/restart 的串行执行；
- 非 internal IPv4 收集、去重和 IPv6 排除。

手动测试应启动 Electron，确认首页显示本机 IP、53317 端口和“运行中”；再访问健康检查。真实局域网和防火墙连通性在阶段 6 双设备连接时验证。

## 阶段 6

双实例回环集成测试覆盖：

- hello、用户审批、welcome 和双方设备信息；
- 待审批 requestId 可通过连接状态快照恢复，nonce 与握手身份保持一致；
- 用户拒绝后双方回到 disconnected；
- 活动连接存在时拒绝第二个 socket；
- 主动 disconnect 在对端同步清理；
- 目标端口拒绝和非法 JSON；
- IPC 的非法 IP、端口、UUID 与未知字段继续由安全测试覆盖。

真实双机手动测试需覆盖 Windows/macOS 双向连接、允许、拒绝、错误 IP、错误端口、防火墙阻止、拔网线和退出应用。当前环境只能完成单机回环自动化与本机 Electron 冒烟测试。

## 阶段 7

自动化测试新增覆盖：

- 已审批连接上的文字/链接发送、接收 DTO 和 ACK 后完成任务；
- messageId 的 TTL/容量去重，以及当前连接态消息白名单；
- 未连接时拒绝创建文字任务；
- 完整 HTTP/HTTPS 链接识别以及其他 scheme 和混合正文拒绝分类；
- 会话历史的倒序、上限、筛选、分页和清空。

协议和 IPC 既有测试继续覆盖空文字、UTF-8 64 KiB 边界、非法类型、危险外链 scheme 和未知字段。真实双机需按开发指南验证 Windows/macOS 双向文字、链接、复制与剪贴板；自动化环境不代替系统剪贴板和默认浏览器手动检查。

文件协议测试同时覆盖 Windows 保留名、非法字符、尾随点/空格和 UTF-8 文件名长度。

## 阶段 8

自动化测试新增覆盖：

- 可移植文件名清洗、Windows 保留名、尾随字符和 UTF-8 字节限制；
- 文件控制消息进入已连接状态白名单；
- 单文件 offer、明确接受、HTTP 二进制流上传以及双方完成状态；
- 中文和空格文件名；
- 目标同名时保留原文件并生成 `name (1).ext`；
- 接收方拒绝后发送方进入 rejected，且不发起上传；
- 既有 HTTP 未知路由、WebSocket 限制、协议边界和 IPC 参数测试继续通过。

真实 Windows/macOS 手动测试仍需覆盖系统选择器、Downloads 权限、防火墙、大文件、0 字节、磁盘不足、文件锁、传输断网和应用退出。单机回环集成测试不能代替这些平台行为。

## 阶段 9

自动化测试新增覆盖：

- 三文件 offer、一次接受、串行 HTTP 上传和任务总进度聚合；
- 中文及空格文件名在多文件任务中的落盘；
- 等待确认时取消一个待传文件，其余文件仍完成且双方最终状态一致；
- 拒绝任务后重试会生成新的 transferId 和 fileId，并可重新接受完成；
- 拖拽路径 IPC 的数量、去重和长度边界；
- 主进程拖拽注册只接受普通文件，并把真实路径替换为一次性 token。

真实双平台还需手动验证系统多选、原生拖拽、当前文件取消、整任务取消、较慢网络下的进度与速度，以及传输中断后的重试。文件夹传输、并行上传和断点续传不在第一版范围。

## 阶段 10

自动化测试新增覆盖：

- 设置和稳定设备 ID 跨 store 实例保留；
- 历史记录原子持久化、动态上限裁剪和 500 字符文字预览；
- 最近设备按设备 ID 去重并保留最新地址；
- 非法设置文件先备份再恢复安全默认值；
- 最近设备 IPC 不接受额外参数，既有 IPC 白名单与 schema 仍完整；
- 所有既有网络、文字、单文件和多文件集成测试继续通过。

手动测试需覆盖设置保存与重启恢复、端口变更成功和占用回退、接收目录失效、文件大小设置、最近设备预填、历史筛选/分页/清空，以及 Windows/macOS 各自的 `userData` 与 Downloads 路径。自动化测试使用临时目录，不替代系统目录权限测试。

## 阶段 11

自动化测试新增覆盖：

- HTTP 按来源限流和 429 响应，以及限流器窗口重置和身份容量上限；
- WebSocket 陈旧/未来时间戳与二进制握手拒绝；
- 文件和目录符号链接拒绝、受保护目录拒绝及规范路径使用；
- 接收磁盘空间不足预检；
- 只清理过期且严格匹配名称的 `.part` 文件；
- 目标路径穿越发布失败；
- 文件选择后即使保持相同大小但身份或修改时间变化，上传仍失败；
- 原有连接、文字、单文件、多文件、取消、重试和持久化测试继续通过。

真实 Windows/macOS 仍需测试 Defender/杀毒软件造成的文件锁、目录 ACL、磁盘空间耗尽、睡眠唤醒、断网、退出应用、局域网防火墙、日志文件位置与长期轮转。单机自动化不能证明跨平台防火墙和文件系统语义。

## 阶段 11.5

自动化测试新增覆盖文字记录和文件任务合并后的时间排序、字节格式化与 0 字节进度边界。selection token 从 1 分钟延长到 10 分钟，以支持用户在统一编辑器中确认待发送列表；目录 token 和网络上传授权的既有限制不变。

手动测试需覆盖统一时间线中的双向文字、链接、文件卡片和内联接收操作；分别验证只发文字、只发文件、文字与文件一起发送、系统多选、拖拽、逐个移除、清空、Enter 发送以及 Shift+Enter 换行。中文等输入法组合输入期间按 Enter 只能确认输入，不能提前发送；发送中连续按 Enter 不得创建重复任务。还需停留超过 10 分钟后尝试发送待选文件，确认授权过期时安全失败并提示重新选择。

## 阶段 11.6

自动化测试新增覆盖历史查询对文字、文件名、设备名和 IP 的规范化匹配，以及 IPC 搜索长度和空白输入边界。手动测试需确认：传输页外层没有滚动条且时间线可独立滚动；文件明细默认折叠；三个全部筛选显示中文；所有历史状态 SVG 居中且错误提示可见；搜索与筛选、分页共同生效；浅色和深色模式切换后重启仍保留，并检查首页、传输、历史、设置及弹窗的对比度。

深色模式需额外检查卡片、表格表头与行、描述列表标签与内容、输入框、下拉列表、确认弹窗、空状态和禁用文字，确保没有浅色背景残留且次级文字清晰。生产构建产物中必须存在独立的 `icon-*.svg`，渲染脚本不得把 Logo 内联为被 CSP 阻止的 `data:` URL。

## 阶段 12

自动化质量门禁继续执行 typecheck、lint、Prettier、Vitest 和生产构建。生产构建后检查 `dist/index.html` 中 JS/CSS 均使用相对资源 URL，且 `dist/assets` 包含独立 Logo 文件，避免打包后的 `file://` 页面白屏或 Logo 丢失。

Windows x64 实机需执行以下安装验收：

1. 从 `release/win-unpacked/Lindu.exe` 启动，检查应用图标、Logo、四个页面和深浅色资源；
2. 运行 NSIS 安装包，分别验证当前用户安装、所有用户安装和自选安装目录；
3. 检查桌面、开始菜单、“已安装的应用”、卸载入口和产品版本信息；
4. 卸载后确认程序文件与快捷方式清除，用户设置和历史按设计保留；
5. 首次监听时仅允许专用网络，验证另一台 Windows/macOS 设备可连接并双向发送文字和文件；
6. 拒绝防火墙访问、删除规则、修改服务端口后重复连接，确认错误提示和恢复流程；
7. 检查中文名、空格、括号、同名文件、0 字节、1 MB、100 MB、大文件、拒绝、断网和应用退出场景；
8. 记录未签名包的 SmartScreen 行为，正式发布前不得把手动放行当作签名替代。

当前配置可在 macOS 生成 NSIS 安装包，但 macOS 无法运行该安装包；跨平台构建结果不能证明 Windows 快捷方式、Defender Firewall、杀毒软件文件锁和卸载语义正确。

## 阶段 13

自动化质量门禁继续覆盖 typecheck、lint、Prettier、Vitest 和生产构建。打包后检查：

- `邻渡.app` 的主可执行文件架构与目标一致；
- Info.plist 中 Bundle ID、版本、最低系统版本、本地网络和受保护目录用途说明正确，ATS 不允许任意加载，且不存在未使用的相机、麦克风、音频采集和蓝牙用途描述；
- 应用资源包含可由 `iconutil` 解析的 ICNS；
- ASAR 包含主进程、Preload、渲染资源、Logo 和生产依赖；
- DMG 同时包含邻渡应用与 Applications 链接，文件名带明确架构。

Apple Silicon 实机执行 arm64 `.app` 和 DMG 冒烟测试：启动、四个页面、深浅色、系统选择器、剪贴板、通知、外链、服务监听和退出。Intel DMG 在当前 Apple Silicon 构建机只做结构检查，必须在真实 Intel Mac 补充启动和传输测试。

手动权限矩阵需覆盖 Gatekeeper 首次阻止与单应用放行、本地网络允许/拒绝/恢复、macOS 防火墙传入连接允许/阻止、Downloads/文稿/桌面目录选择、应用移入废纸篓以及设置历史保留。不得用全局关闭 Gatekeeper 或批量清除 quarantine 代替真实权限流程。

## 1.1 自动发现与可靠性

自动化测试覆盖发现广告 strict schema、自身与陈旧消息拒绝、数据报来源 IP 使用、设备过期，以及传输剩余时间边界。既有 HTTP/WebSocket 集成测试仍必须全部通过；受限沙箱若禁止回环监听，应在允许本机 socket 的测试环境重跑，不能把 `EPERM` 当作产品失败或跳过用例。

Windows/macOS 实机手动验证：两台设备同网后 5–10 秒内互相出现，点击连接仍显示对端审批；在同时启用 Wi-Fi、有线网卡、扩展坞或 VPN 时确认实际同网段接口仍能发现。发现同时使用逐接口组播和网段定向广播；阻止 UDP 53318 后设备会在约 16 秒消失且手动 IP 仍可连接。更改服务端口和设备名后广告应更新。传输大文件时检查系统不会仅因应用挂起而中断、速度稳定后出现合理的预计剩余时间、退出出现确认、继续传输不会取消任务、明确退出会清理临时文件。接收完成后“在文件夹中显示”应定位实际的重名安全文件；移动或删除文件后操作应安全失败。

## 1.2 文件夹传输验收矩阵

后续阶段必须逐步覆盖：空目录、0 字节文件、中文、空格、括号、深度 20/21、999/1,000/1,001 个文件、总大小边界、512 字节相对路径边界、NFC/NFD、大小写冲突、Windows 保留名、尾随点/空格、绝对路径、盘符、UNC、反斜杠、`.`、`..`、符号链接、扫描后替换、manifest 缺片/重复/乱序/超量/摘要不一致、上传乱序、重复 token、断网、退出、目录失效、磁盘不足和同名文件夹。

发布测试必须确认失败或取消不产生可被误认为完成的目录，启动清理只处理名称和 ownership marker 同时合法的过期 staging。真实 Windows/macOS 还需验证大量小文件性能、杀毒软件文件锁、大小写敏感/不敏感文件系统以及 Finder/Explorer 中的发布可见性。
