# 测试指南

## v0.5.0 正式分发与安全更新

阶段 0 只冻结正式分发、更新信任链、联网隐私、凭据和验收边界，不新增自动化。

阶段 1 自动化覆盖 stable 语义版本、更新状态与错误码唯一性、状态相关字段、公开发布信息严格脱敏、更新 IPC 无参数边界，以及 `updates.json` 默认值、持久化、独立性和未知 schemaVersion 安全备份。shared channel 在阶段 1 只冻结契约，主进程 handler 与 Preload API 留到对应实现阶段，因此 renderer 尚不能发起更新操作。

阶段 2 自动化检查开发配置仍禁用签名/notarization、正式 macOS 配置强制 Developer ID 签名并启用 Hardened Runtime/notarization、主应用与辅助进程使用最小 entitlements，以及凭据预检不会输出 secret 值。真实证书环境还必须执行 `pnpm package:mac:release:arm64` 与 `pnpm package:mac:release:x64`，随后对 `.app` 和 DMG 运行 `pnpm verify:mac:release -- <app-path> <dmg-path>`，并在隔离机器验证 stapled ticket、离线 Gatekeeper 和首次启动；未执行时保持待签字。

阶段 3 自动化检查开发配置仍允许未签名测试包，正式 Windows 配置强制签名、证书主题与更新发布者使用同一 `WIN_CSC_NAME`、只使用 SHA-256 并配置 RFC 3161 时间戳。真实 Windows 证书环境必须执行 `pnpm package:win:release`，再以 `WIN_CSC_NAME` 运行 `pnpm verify:win:release -- release/win-unpacked/Lindu.exe release/Lindu-Setup-0.5.0-x64.exe`，核对两者 Authenticode 状态、证书主题与脚本输出的 SHA-256，并完成干净系统安装、覆盖升级、卸载和 SmartScreen 签字。

阶段 4 自动化使用可注入 updater 覆盖固定 GitHub owner/repo、stable-only、禁止降级与静默安装、无认证请求头、每天最多一次自动检查、检查/下载状态机、进度边界和 provider 元数据脱敏。测试输入包含下载 URL、本地安装器名和摘要，renderer 投影不得出现这些字段或值；非稳定版本和非法元数据必须返回 `UPDATE_METADATA_INVALID`。开发环境不启动联网检查，正式包的真实 GitHub Release 行为留到阶段 8。

阶段 5 通过 TypeScript 契约和 IPC schema 一致性验证所有更新操作都有具名 Preload 方法，设置修改只接受布尔开关，其余操作不接受 URL、路径、token 或其他参数。手动检查设置页的自动检查开关、检查中禁用、可下载、下载进度、取消、已下载摘要、错误提示和深浅色布局。阶段 6 前安装按钮必须保持禁用，直接调用安装 IPC 返回 `UPDATE_INSTALL_BLOCKED`。

阶段 6 自动化覆盖下载完成后的动态安装就绪状态、门禁失败不准备安装、门禁通过后只允许消费一次 prepared install，以及平台安装调用参数。手动测试在配对弹窗、connecting/authenticating、文件或文件夹传输、校验/发布、自动重连和队列等待期间点击安装，必须返回阻塞且任务不受影响；空闲时确认安装后所有新 IPC 应被拒绝，恢复记录与 stores 完成写入、服务正常停止后才启动安装器。

阶段 7 自动化覆盖标签与 package 版本精确匹配、发布输入符号链接拒绝、允许产物筛选、稳定排序、SHA-256 与审计 JSON，以及 workflow 只由 `v*` 标签触发、使用 frozen lockfile、执行平台验证并仅创建 Draft Release。CI secrets 只映射为签名工具要求的环境变量；日志与上传 artifact 中不得出现证书、密码、notarization key 或发布令牌。

## v0.3.0 测试路线

阶段 0 只锁定测试边界，不新增测试代码。后续自动化必须覆盖历史 ID 批量上限与去重、筛选/日期清理、数量与时间保留规则组合、旧 store 迁移、最近设备 alias 保留、诊断 DTO 脱敏、固定目录 IPC、日志普通文件边界和错误建议映射完整性。

阶段 1 自动化覆盖合法 settings/recent-devices v1 到 v2 的迁移、既有字段保持、迁移后文件版本、最近设备地址更新时 alias 保留、保留天数设置边界、历史批量删除 ID 去重、条件清理非空约束和 alias 长度。未来版本或非法 store 仍走既有损坏备份路径。

阶段 2 自动化覆盖历史统计、查询匹配、UUID 删除、复合条件预览与清理，以及启动时按保留天数删除过期摘要。手动检查单条删除、当前页多选、当前筛选、失败状态和 30/90/180 天以前的清理确认数量；每次操作后都确认接收目录中的真实文件与文件夹保持不变，并在深浅色模式下检查工具栏、下拉菜单和统计文字。

阶段 3 自动化覆盖最近设备备注新增/移除、按 deviceId 删除、清空和地址更新后备注保留。双机手动检查在线标记、一键连接使用发现到的新地址、离线设备回填旧地址，以及设置备注后对端审批弹窗和发现广播中不出现本地备注。

阶段 4 自动化覆盖日志文件名白名单、普通文件边界、当前日志保留、按日期清理和 IPv4 网段脱敏。手动导出报告后搜索设备名、备注、文件名、文字、UUID、完整 IP 和绝对路径，确认均不存在；取消保存不能产生临时文件。分别检查打开数据/日志目录、清理旧日志、保留天数启动清理，以及 Windows 文件锁下清理失败不影响应用运行。

阶段 5 自动化检查每个稳定错误码都有非空中文建议。手动制造错误 IP、关闭端口、接收目录失效、磁盘空间不足、源文件移动、接收拒绝、传输超时和中途断线，确认建议与入口匹配；点击重试必须先显示“从头传输”确认，取消确认不得创建新任务。

## v0.4.0 测试路线

v0.4.0 按 [安全配对与可恢复传输设计](v0.4.0.md) 分阶段增加密码学向量、握手篡改、验证码不一致、身份冲突、协议降级、密文位翻转、序号重放、分块乱序/重复/跨文件替换、最终摘要失败、暂停/断网/进程重启/系统重启恢复和源文件变化测试。所有攻击用例必须失败关闭，且不得发布文件或遗留无 ownership 的 staging。

阶段 2 自动化覆盖身份跨重启稳定、Ed25519 签名验证、挑战内容篡改、安全存储不可用、公钥指纹损坏、公私钥不匹配、可信记录持久化、身份冲突拒绝、伪造指纹和显式取消信任。身份故障用例必须抛错，不允许自动生成新身份覆盖问题数据。真实 Windows 和 macOS 的系统安全存储及钥匙串行为在阶段 10 候选包中手动验证。

阶段 3 自动化覆盖双方 X25519 共享秘密相同、transcript 任一 nonce 变化导致 confirmation key 变化、六位验证码一致、双方确认前不写可信记录、拒绝、超时、已信任密钥免配对、同 deviceId 换钥拒绝，以及配对/可信设备 IPC 严格参数校验。UI 手动检查验证码可读性、深浅色对比度、关闭弹窗等同拒绝、设置页逐台/全部取消信任；真正双机握手在阶段 4 接入网络后执行。

阶段 4 自动化覆盖首次连接双方得到相同 requestId/验证码且必须双端接受、Ed25519 proof 签名失败、旧 v2 明文 hello 拒绝、连接后文字不出现在线缆帧、双向 AEAD 解密、tag 篡改、sequence 重放、transcript nonce 变化、连续密文消息、原有文件与文件夹控制回归。手动双机检查首次配对弹窗、任一端拒绝、验证码超时、取消信任后重新配对、已信任重连和抓包看不到文字/文件名；阶段 6 前抓包仍可看到 HTTP 文件正文，因此不得把本阶段结果记录为完整文件端到端加密验收。

v0.4.0 阶段 5 自动化覆盖已授权文件的流式 SHA-256、0 字节摘要、过期大小快照、安全 file offer 与文件夹 manifest 的摘要/块数 schema、正常文件和文件夹回归，以及保持长度不变的内容替换不得发布。手动双机应在接受 offer 后替换源内容并确认双方失败、目标文件不可见、临时文件被清理；同时用 0 B、4 MiB 边界和大文件观察预计算期间内存不随文件大小增长。HTTP 抓包仍能看到正文，机密性验收留到阶段 6。

v0.4.0 阶段 6 自动化覆盖单块密码学往返、密文位翻转、跨索引重放、描述长度不一致、0 字节、跨 4 MiB 的双块文件、文件夹回归、真实 HTTP 密文篡改清理和分块路由限流。手动双机需抓包确认正文与文件内容片段不再明文出现，并验证 4 MiB、4 MiB+1、大文件、同一认证块重试、错误 tag、断网和退出不会发布未完整文件。暂停和断线后保留块不属于本阶段，阶段 7 前仍按失败清理。

v0.4.0 阶段 7 自动化覆盖首个 4 MiB 块认证后暂停、verified ranges 校验、只补传缺失块，以及同一可信身份在两分钟内自动重连且不重复弹连接审批。主动断开仍按取消或连接失败处理，不能被误判为可恢复网络抖动。

v0.4.0 阶段 8 自动化覆盖普通文件与文件夹在至少一个块完成后暂停、销毁协调器、从加密记录重建、重新复核源和 staging、协商 verified ranges 并完成发布；同时覆盖密文损坏、七天过期、非归属路径不删除和恢复 store 不泄露明文源路径。双机手动测试分别在 Windows 和 macOS 上发送跨三个以上块的文件与文件夹：完成首块后暂停并退出一端应用，重新启动后连接原可信设备，确认任务显示“可继续”，点击继续并核对最终 SHA-256。再分别修改发送源、删除接收 staging、撤销设备信任，确认旧任务不能继续且不会发布不完整内容。正常退出用于验证恢复，任务卡“取消”用于验证 staging 与记录立即清理，两者语义不可混用。

v0.4.0 阶段 9 自动化新增 canonical verified range 的稀疏合并、乱序/重叠、空区间和越界拒绝，以及 IPC channel/schema 一致性、恢复 staging 清理豁免和现有攻击回归。手动检查应用启动后恢复任务无需等待新事件即可出现；未连接、连接错误设备、正确设备在线、正在重连和正在校验时按钮与提示必须匹配。导出诊断报告后搜索路径、文件名、摘要、bitmap、指纹、公钥和 token，确认只出现可恢复任务数量。

## 1.1 自动发现与可靠性

自动化测试覆盖发现广告 strict schema、自身与陈旧消息拒绝、数据报来源 IP 使用、设备过期，以及传输剩余时间边界。既有 HTTP/WebSocket 集成测试仍必须全部通过；受限沙箱若禁止回环监听，应在允许本机 socket 的测试环境重跑，不能把 `EPERM` 当作产品失败或跳过用例。

Windows/macOS 实机手动验证：两台设备同网后 5–10 秒内互相出现，点击连接仍显示对端审批；在同时启用 Wi-Fi、有线网卡、扩展坞或 VPN 时确认实际同网段接口仍能发现。发现同时使用逐接口组播和网段定向广播；阻止 UDP 53318 后设备会在约 16 秒消失且手动 IP 仍可连接。更改服务端口和设备名后广告应更新。传输大文件时检查系统不会仅因应用挂起而中断、速度稳定后出现合理的预计剩余时间、退出出现确认、继续传输不会取消任务、明确退出会清理临时文件。接收完成后“在文件夹中显示”应定位实际的重名安全文件；移动或删除文件后操作应安全失败。

双机手动测试需在同一次发送中同时加入文字、多个文件和一个文件夹，确认界面显示发送中/排队位置，对端依次收到文字、文件 offer、文件夹 offer；在第一项等待接受时后续项不得提前出现。再分别验证拒绝、失败和取消后队列继续推进，移除尚未启动项不会影响当前任务，断线会清除等待项且重连到另一设备后不会自动发送旧内容。用大文件让后续文件夹等待超过 10 分钟，确认已入队授权仍可启动。

阶段 7 自动化覆盖前台静默、后台文字/offer 通知隐私、终态通知有界去重，以及成功/失败/取消/拒绝数量汇总。通知测试使用注入 presenter，不调用真实操作系统通知。

Windows/macOS 手动测试需分别允许和拒绝通知权限；在窗口聚焦、失焦、最小化和 macOS 关闭全部窗口四种状态下验证行为。后台收到文字、链接、文件 offer、文件夹 offer、成功和失败时应有通知，正文、文件名、文件夹名和路径不得出现在通知中；点击通知应恢复或重建主窗口。前台不应弹通知，同一终态不得重复通知。任务卡需检查全成功、部分取消、部分失败、整体拒绝和超过 20 个失败项的摘要、暗色对比度与长名称截断。
