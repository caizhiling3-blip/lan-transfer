# v0.3.0 数据管理与故障诊断设计

## 目标

v0.3.0 在不改变局域网通信协议 v2 的前提下，提高本地数据可管理性、设备重连体验和故障排查能力。版本只管理历史摘要、最近设备和应用日志，不自动删除用户收到的真实文件。

锁定决策：

- 历史按天自动清理默认关闭，升级后不主动删除既有记录；
- 清理历史永远不删除接收目录中的真实文件或文件夹；
- 最近设备不等于可信设备，连接仍需对端明确审批；
- 诊断报告不包含正文、文件名、完整路径、令牌或未脱敏设备标识；
- 不新增第三方依赖，不升级 WebSocket 协议版本。

## 功能范围

### 历史管理

- 删除单条记录，或一次批量删除最多 100 条记录；
- 按当前筛选条件清理，并在确认前返回匹配数量；
- 按日期、状态清理，支持只清理失败、取消和拒绝记录；
- 显示历史总数、当前筛选匹配数和 `history.json` 文件大小；
- 设置可选历史保留天数，`null` 表示关闭，允许范围为 1–3650 天；
- 保留既有 100–10000 条数量上限，数量和时间规则同时生效时任一规则都可淘汰记录。

清理只删除 `history.json` 中的摘要。接收文件、发送源文件、设置、最近设备和日志均不受影响。

### 最近设备管理

- 首页展示最近设备、最后连接时间和自动发现在线状态；
- 一键填入地址并发起既有连接流程；
- 设置最多 64 个字符的本地备注，删除单个设备或清空列表；
- 备注仅写入本机 `recent-devices` store，不进入发现广播、握手或日志；
- 设备地址变化时继续按 deviceId 去重并更新地址，备注保持不变。

### 诊断与日志

- 展示应用版本、操作系统、CPU 架构、服务/发现/连接状态、监听端口、活动任务数、历史数量和已知数据占用；
- 允许打开 Electron 已知的 userData 与日志目录，不向 renderer 返回真实路径；
- 通过系统保存对话框导出 UTF-8 JSON 诊断报告；
- 诊断报告只包含脱敏状态和稳定错误码，不包含原始日志正文；
- 提供日志占用统计、手动清理和保留天数设置，默认保留 30 天；
- 日志清理只匹配日志目录中的已知普通文件，不递归、不跟随符号链接、不删除当前正在写入的文件。

### 失败恢复体验

- 为稳定错误码提供独立的本地处理建议，不把建议写进网络协议；
- 任务卡显示失败原因和建议操作；
- 对连接错误提供重新连接入口，对目录错误提供前往设置或重新选择目录入口；
- 重试前明确提示文件和文件夹会从头传输，不承诺断点续传；
- 文件夹失败摘要继续限制展示数量，避免大量失败项拖慢 renderer。

## IPC 草案

所有契约、schema 和 DTO 继续定义在 `src/shared`，Preload 只暴露具名方法。

```text
history:get-stats
history:delete
history:preview-cleanup
history:cleanup

recent-devices:list
recent-devices:update-alias
recent-devices:remove
recent-devices:clear

diagnostics:get-summary
diagnostics:export-report
diagnostics:open-data-directory
diagnostics:open-log-directory
diagnostics:get-log-stats
diagnostics:clear-logs
```

建议请求边界：

- `history:delete` 只接受 1–100 个 UUID historyId，拒绝重复 ID 和未知字段；
- cleanup 条件复用历史筛选 DTO，并额外接受严格的 `before` 时间戳；
- 先调用 `preview-cleanup` 获取数量，确认后提交同一规范化条件，不把预览结果作为权限凭证；
- recent device 操作只接受 UUID deviceId，alias 为空表示移除备注；
- 目录打开和诊断导出不接受 renderer 路径；导出位置由主进程系统对话框选择；
- 所有事件和返回 DTO 不包含 Electron event、绝对路径或原始异常堆栈。

## 存储迁移

`settings` 从 schemaVersion 1 迁移到 2，增加：

```ts
historyRetentionDays: number | null
logRetentionDays: number
```

旧数据迁移默认值为 `null` 和 `30`。迁移必须先读取未知 JSON、按已知旧版本逐步转换，再使用最新 Zod schema 严格验证；未知未来版本不得被静默降级。

`recent-devices` 增加可选 `alias`，需要独立 schemaVersion 迁移。`history` 记录结构不变，单条或批量删除后继续使用 electron-store 原子保存。

自动历史清理在应用启动和成功保存保留策略后执行；不使用高频定时器。日志过期清理在应用启动后异步执行，失败只记录安全错误，不阻止窗口和局域网服务启动。

## 安全边界

- renderer 不能读取 store、日志或目录路径；
- 数据大小统计只针对主进程预先确定的文件，不接受 glob 或任意路径；
- 删除历史只按已存在的 UUID 匹配，不接受数组索引；
- 日志清理拒绝目录、符号链接、未知文件名和当前活动日志；
- 诊断报告中的 IP 保留网段并隐藏主机位，deviceId/connectionId/transferId 不导出；
- 设备名、备注、文字预览、文件名和文件夹名不进入诊断报告；
- 导出使用临时文件加安全替换，取消保存不产生文件；
- 打开目录使用主进程持有的固定目录，禁止 `shell.openExternal` 或自定义 scheme。

## 阶段

0. 本文档、产品边界、IPC 草案、迁移与脱敏规则；
1. shared 契约、设置/最近设备迁移及存储单元测试；
2. 历史统计、单条/批量/条件清理和历史页面；
3. 最近设备列表、备注、删除、在线状态合并和一键连接；
4. 诊断中心、目录操作、报告导出和日志生命周期；
5. 错误处理建议、恢复入口和任务卡体验；
6. 数据迁移、Windows/macOS 实机验收及 v0.3.0 发布。

每阶段独立执行 typecheck、lint、format check、test 和 build，完成后单独提交和推送。阶段 6 前不得宣称真实 Windows/macOS 验收通过。

## 非目标

v0.3.0 不实现断点续传、暂停恢复、文件夹同步、文件内容 SHA-256、端到端加密、永久信任、公网中继、账号、云历史、二维码、自动更新、开机启动、移动端、多设备群发或自动删除真实接收文件。
