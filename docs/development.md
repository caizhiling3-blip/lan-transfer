# 开发指南

## 初始化

```bash
pnpm install
```

## 启动开发环境

```bash
pnpm dev
```

Vite 启动渲染进程开发服务器，Electron 主进程和 Preload 由 `vite-plugin-electron` 构建并启动。

应用名称为「邻渡」。应用使用固定左侧菜单；传输页只滚动内部活动时间线，其他页面使用右侧内容区滚动。首页连接状态以中文徽标展示：未连接、正在连接、等待对方确认、已连接、正在断开或连接异常。右上角按钮可切换深浅色主题，选择会在本机 renderer 存储中保留。

## 检查

```bash
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
```

项目使用 TypeScript strict 模式，并额外开启 `noUncheckedIndexedAccess` 和 `exactOptionalPropertyTypes`。代码风格由 ESLint 与 Prettier 管理。

协议输入使用 Zod 做运行时校验，静态类型优先由 schema 推导。纯 shared 单元测试使用 Vitest：

```bash
pnpm test
pnpm test:watch
```

## Windows 打包开发

阶段 12 使用 `electron-builder`。安装此依赖是为了生成 Windows x64 应用目录和 NSIS 安装包；`build/icon.ico` 是 Windows 打包图标，渲染进程复用其高质量源文件 `build/icon.svg`。

建议在 Windows x64 环境执行：

```bash
pnpm package:win:dir
pnpm package:win
```

`package:win:dir` 先生成 `release/win-unpacked`，适合验证应用启动、资源路径和服务监听；`package:win` 生成正式的安装向导。两条命令都会先执行生产构建。当前配置可以在项目的 macOS 开发机生成 NSIS 包，但跨平台产物不能代替 Windows 实机的安装、卸载和防火墙验收；若构建机提示缺少兼容工具链，应改在 Windows x64 环境构建。

生产渲染资源使用相对 URL，以保证 `BrowserWindow.loadFile` 加载 `dist/index.html` 时能找到 JS、CSS 和 Logo。打包输出位于 `release/`，不得提交到 Git。

## macOS 打包开发

阶段 13 继续使用 electron-builder，不增加第三方依赖。`build/icon.icns` 是从品牌 SVG 生成并通过 `iconutil` 反向解析验证的多分辨率 macOS 图标。

```bash
pnpm package:mac:dir
pnpm package:mac:arm64
pnpm package:mac:x64
pnpm package:mac
```

- `package:mac:dir`：生成当前 CPU 架构的未压缩 `.app`，用于本机冒烟测试；
- `package:mac:arm64`：生成 Apple Silicon DMG；
- `package:mac:x64`：生成 Intel DMG；
- `package:mac`：依次生成两个架构的 DMG。

当前测试包显式禁用代码签名、notarization 和 Hardened Runtime，只允许开发验收，不适合公开分发。应用的最低系统版本为 macOS 12，Bundle ID 固定为 `com.lindu.transfer`。第一版不使用 Bonjour，因此 Info.plist 只声明本地网络用途，不声明 `NSBonjourServices`。

## IPC 开发约束

- 新 handler 必须使用 `registerIpcHandler`，不得直接分散调用 `ipcMain.handle`。
- channel、请求类型及 Zod schema 必须先加入 `src/shared/ipc`。
- Preload 只能增加具名方法，禁止暴露通用 IPC 方法。
- renderer 不得导入 Electron、Node.js 或主进程模块。

## 本地服务检查

开发模式启动后，首页会展示当前非 internal IPv4、实际服务端口和服务状态。可在本机验证健康检查：

```bash
curl http://127.0.0.1:53317/health
```

预期返回 HTTP 200 和协议版本。若端口被其他程序占用，首页应展示 `PORT_IN_USE` 对应的中文错误；本阶段不会自动选择随机端口。

## 双设备连接检查

在两台同局域网设备运行应用，在主动方输入另一台首页显示的 IPv4 和端口 53317。接收方必须出现审批弹窗；允许后双方显示对方设备信息，拒绝后双方回到未连接。继续检查主动断开、应用退出和错误端口。

macOS 或 Windows 防火墙提示应只允许受信任的专用网络。阶段 6 不发送文字或文件。

## 双设备文字检查

完成上述连接后进入“传输”页面：

1. Windows 向 macOS 发送普通文字，确认对端立即显示并可一键复制；
2. macOS 向 Windows 反向发送普通文字；
3. 双向发送完整 HTTP/HTTPS 链接，确认显示“链接”标记；
4. 点击“打开链接”，确认只有用户操作后才交给默认浏览器；
5. 使用“读取剪贴板”填入编辑框，再发送；
6. 断开连接，确认发送按钮禁用；输入超过 64 KiB 时同样不能发送；
7. 在同一次应用运行期间切换页面，确认最近文字仍可显示。

文字和文件历史会写入本地 store；文字仅保存最多 500 个字符的预览。重启应用后可以在传输页恢复最近文字摘要，也可以在历史页面筛选或清空记录。

## 双设备文件检查

建立连接后在发送方进入“传输”，点击“添加文件”或把文件拖入统一编辑器。选择结果先进入待发送区，不会立即通知对端；可以逐个移除、清空，或同时输入一段文字后点击“发送”。选择授权保留 10 分钟。接收方会自动进入传输页，并在对应时间线卡片中选择接收到系统 Downloads、通过系统选择器更改本次目录，或拒绝文件。

分别从 Windows 和 macOS 双向验证普通文件、中文文件名、空格、括号、0 字节、1 MB、100 MB、接近设置上限的大文件和同名文件。观察双方文件名、MIME、大小、进度、速度及最终状态；同名目标不能被覆盖。传输过程中拔网线或退出接收端，确认最终文件不出现，随机 `.part` 文件被清理。

继续选择 2–20 个文件并验证严格串行上传、总进度与逐文件状态。分别测试系统多选和拖拽；拖入文件夹或超过 20 个文件应被拒绝。测试取消整个任务、取消当前文件、取消待传文件，以及失败/拒绝/取消后的重试；确认重试创建新任务，已成功文件不回滚且同名目标不覆盖。

统一编辑器还需检查：只发送文字、只发送文件、文字与文件一起发送、移除单个待发送文件、清空待发送区，以及 `Command+Enter`（macOS）/`Ctrl+Enter`（Windows）快捷发送。文字与文件一起发送时会依次形成两条独立记录；文字发送失败时不会继续发起文件 offer，避免在连接已经异常时制造第二个失败任务。若连接在正式发送前断开，待发送文件会被清空并要求重新选择，避免重连到其他设备后误发。

## 本地设置与历史检查

设置页面可修改设备名、服务端口、最大单文件大小和历史上限，默认接收目录必须通过系统目录选择器授权。修改端口后确认服务立即以新端口运行；占用目标端口时应显示错误并继续使用旧端口。重启应用后确认设备 ID、设置和历史均保持不变。

成功连接设备后，断开并重启应用，首页应使用最近设备预填 IP 和端口，但不能自动连接。完成双向文字、文件、拒绝和取消操作后，在历史页面按方向、类型和状态筛选，检查分页与清空确认框。将历史上限调低后应立即删除最旧记录。

本地文件位于 Electron 标准 `userData` 目录，不应手工编辑。测试损坏配置时应先备份整个测试用户数据目录；应用会把无法通过校验的 store 改名为 `.invalid-时间戳` 并恢复默认值。

历史页搜索框会匹配文字摘要、文件名、设备名和 IP，并与方向、类型、状态筛选共同生效。搜索和筛选必须在分页前完成；“全部方向”“全部类型”“全部状态”应显示中文选项，不得显示默认 `Select`。状态图标应在浅色、深色和各缩放比例下保持居中。

## 异常与安全检查

阶段 11 后应额外执行：

1. 尝试拖拽文件夹、文件符号链接和相对路径，确认无法签发发送 token；
2. 尝试选择磁盘根、系统目录、应用数据目录或安装目录作为接收目录，确认被拒绝；
3. 将已选择文件替换、修改或改为符号链接后再接受，确认任务以 `FILE_NOT_FOUND` 失败；
4. 上传中断网或暂停数据超过 30 秒，确认双方超时且 `.part` 被清理；
5. 重复提交同一上传 token，确认不会覆盖或生成第二份文件；
6. 构造错误 Content-Length、chunked 上传、错误 MIME、过期 token、乱序文件和超量 body，确认请求失败；
7. 创建严格匹配命名且超过 24 小时的测试 `.part` 文件，重启后确认仅该文件被清理；
8. 检查 Electron 标准日志目录，确认包含应用、服务、连接和传输状态，但不包含文字正文、剪贴板、token、文件内容或完整文件路径。

限流测试应只在隔离环境执行，避免把正常设备暂时限制。磁盘不足、Windows 文件锁和真实断网仍需在双平台手动验证。

## 阶段

项目严格按需求与架构、初始化、共享协议、安全基础、本地服务、设备连接、文字、文件、多文件、存储、安全完善、双平台打包和验收的顺序推进。
