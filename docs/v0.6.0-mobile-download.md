# v0.6.0 电脑发送到手机设计

## 范围

在既有短时扫码会话内增加 PC 到手机的反向文件传输。PC 用户通过系统文件选择器选择 1–20 个普通文件；手机扫码后读取文件清单，并由用户逐个点击下载。第一版不发送文件夹、不自动连续触发多个浏览器下载、不生成 ZIP，也不要求手机安装应用。

## 安全边界

- 沿用移动会话的 256 bit fragment 密钥、会话有效期、来源校验、nonce 防重放、限流及 `Cache-Control: no-store`。
- renderer 只持有短时 selection token 和净化后的文件元数据，不获得文件路径。主进程消费 selection token 后独占保存授权源。
- 手机必须先用二维码密钥请求下载清单。首次成功请求把下载批次绑定到来源 IP；之后的清单及文件请求必须来自同一地址。
- 清单为每个文件返回独立高熵下载令牌。令牌只存在于 URL path，绝不包含本机路径，不写入历史、诊断或业务日志，并随二维码会话关闭或过期失效。
- 下载前通过已打开的文件句柄重新核对普通文件类型、大小、设备号、inode 和修改时间；选择后被替换或变化的文件失败关闭。
- 响应使用净化后的 `Content-Disposition` 文件名、固定 `Content-Length`、`application/octet-stream` 或已知 MIME，并禁止缓存、嗅探和跨源读取。

## 接口与交互

- IPC `mobile-upload:publish-downloads`：PC 提交 1–20 个现有文件 selection token，主进程消费并发布到当前移动会话。
- IPC `mobile-upload:clear-downloads`：清除当前反向发送批次及所有下载令牌。
- `GET /mobile/:sessionId/downloads`：使用移动认证 header 查询当前文件清单；无批次时返回空列表。
- `GET /mobile/:sessionId/downloads/:fileId/:downloadToken`：同源地址凭短时令牌下载单个文件。

PC 二维码弹窗增加“电脑发到手机”区域，可选择、替换和清空文件。手机页面同时展示“发送到电脑”和“从电脑接收”两个区域，每秒轮询下载清单；文件名过长单行省略，用户点击后由浏览器保存。二维码关闭、过期或 PC 清空后，未开始的下载立即失效。

## 阶段

1. 本文档冻结范围、威胁模型、IPC、HTTP 和浏览器限制。
2. 增加 shared DTO、schema、IPC 白名单和 Preload 具名方法。
3. 实现主进程授权消费、来源绑定、文件身份复核和流式下载。
4. 实现 PC 选择区、手机响应式下载区、状态与错误提示。
5. 完成单元/集成、安全回归、构建及 iOS Safari/Android Chrome 实机验收。

每阶段遵循 `docs/development.md` 的质量门禁。阶段 5 实机完成前继续视为测试功能。
