# v0.4.0 安全配对与可恢复传输设计

## 目标与边界

v0.4.0 把邻渡的局域网通信升级为协议 v3，提供可验证设备身份、端到端加密、文件完整性校验、固定分块上传、暂停/继续、断线续传和应用重启恢复。

版本仍保持单对单局域网直连，不引入公网中继、账号、云端密钥、云历史、多设备群发、文件夹同步、自动剪贴板同步、自动更新或移动端。v3 不与 v2 静默降级；发现 v2 对端时显示明确的版本不兼容提示，避免降级攻击。

锁定决策：

- 不新增密码学依赖，使用 Node.js `crypto` 提供的 Ed25519、X25519、HKDF-SHA-256、SHA-256 和 AES-256-GCM；
- 长期 Ed25519 私钥只在主进程使用，并通过 Electron `safeStorage` 加密后保存；renderer、Preload、日志、诊断报告和网络消息都不得获得私钥；
- 首次配对必须由两端用户核对同一组六位验证码并分别确认；确认前不建立信任；
- 已配对设备只有在长期公钥签名验证成功后才可自动通过连接审批；用户可随时取消信任；
- 每次连接使用新的 X25519 临时密钥和随机 nonce，派生独立的发送、接收和文件密钥；长期身份密钥不直接加密业务内容；
- 控制消息和文件内容均使用 AEAD；序号、方向、协议版本和连接 ID 进入附加认证数据，防止篡改、重放和跨连接挪用；
- 文件使用固定大小分块独立加密，每块可单独校验和重传；最终文件仍需完整 SHA-256 通过后才能发布；
- 暂停只停止调度新分块，不撤销已经写入并验证的分块；取消继续清理 staging；
- 重启恢复只恢复用户已明确授权的本机路径和接收目录，路径状态通过 `safeStorage` 加密持久化且永不进入 renderer；
- 任何恢复都重新验证源文件大小、修改时间、设备号/inode（可用时）和完整 SHA-256，变化后必须重新选择，不能继续旧任务。

## 威胁模型

需要防止：

- 同一局域网内被动抓包读取文字、链接、文件名、文件内容或控制状态；
- 主动中间人替换临时密钥、冒充已信任设备或强制降级到 v2；
- 旧握手、旧密文、旧分块、旧上传授权和旧恢复记录被重放；
- 密文被截断、乱序、跨文件复用或传输完成状态被伪造；
- 已撤销设备继续自动连接；
- 本地持久化任务泄露完整源路径、保存路径、会话密钥或文件内容；
- 应用退出、断网、磁盘不足或校验失败留下可见的伪完整文件。

不声称防止：

- 首次配对时用户不核对验证码而接受主动中间人；
- 操作系统、当前用户账户或邻渡主进程已被完全控制；
- 对方设备在解密后主动泄露收到的内容；
- 流量分析推断连接时间和近似数据量；
- 删除原文件后仍能恢复发送任务。

## 密钥与身份

每台设备首次启动 v0.4.0 时生成 Ed25519 长期身份密钥。公钥指纹使用公钥 DER 的 SHA-256，并以分组短指纹供用户识别。私钥 PKCS#8 DER 先交给 `safeStorage.encryptString`，store 只保存 Base64 密文、公开公钥、指纹和密钥格式版本。

每次连接双方生成 X25519 临时密钥，并对包含以下字段的规范化 transcript 进行 Ed25519 签名：

```text
protocolVersion
initiatorDeviceId
responderDeviceId
initiatorNonce
responderNonce
initiatorEphemeralPublicKey
responderEphemeralPublicKey
initiatorIdentityPublicKey
responderIdentityPublicKey
```

X25519 共享秘密经过 HKDF-SHA-256 派生：

- initiator-to-responder 控制密钥；
- responder-to-initiator 控制密钥；
- 文件根密钥；
- transcript confirmation key。

原始共享秘密和派生密钥只存在于主进程内存；断开连接后清除引用，不写 store。

## 首次配对流程

1. 双方完成临时密钥交换和 transcript 签名校验，但连接保持 `pairingRequired`；
2. 双方从 transcript confirmation key 派生相同的六位验证码；
3. UI 显示设备名、系统、地址、公钥短指纹和验证码；
4. 两端分别选择“验证码一致”或拒绝；
5. 两端都确认后交换加密的 pairing confirmation，并保存对方 deviceId、公钥、指纹、首次/最后确认时间；
6. 任一端拒绝、超时、断线或验证码不一致时立即销毁会话，不写信任记录；
7. 以后连接必须证明持有已保存公钥对应的私钥；deviceId 相同但公钥变化时按身份冲突拒绝，不能自动覆盖。

配对记录是本机信任，不随最近设备删除而删除。取消信任后，下一次连接重新执行验证码配对。

## 加密控制消息

握手完成后的 WebSocket 消息外层改为最小加密 envelope：

```ts
interface EncryptedEnvelope {
  version: 3
  connectionId: string
  sequence: number
  ciphertext: string
  authenticationTag: string
}
```

nonce 由连接随机 nonce 前缀和单调递增的 64 位 sequence 组成。每个方向维护独立序号；重复、回退、跳跃超过窗口、认证失败或 connectionId 不符都关闭连接。解密后的业务消息继续使用严格判别联合和 messageId 去重，但敏感 payload 不再明文出现在 WebSocket 帧中。

## 文件摘要与分块

- 默认明文块大小 4 MiB，0 字节文件的块数为 0；
- offer 包含文件大小、块大小、块数和完整文件 SHA-256；
- 单块密钥从文件根密钥、transferId、fileId 和 chunkIndex 派生；
- 每块使用独立 AES-256-GCM nonce，AAD 包含版本、连接 ID、transferId、fileId、chunkIndex、明文偏移和明文长度；
- 上传使用 `PUT /v3/transfers/:transferId/files/:fileId/chunks/:chunkIndex`，必须提供精确 `Content-Length`；
- 接收端只接受已批准任务范围内的合法缺失块，认证成功后写入随机 staging 文件对应偏移并记录 verified bitmap；
- 重复上传已验证块返回幂等成功，但密文或元数据不一致时终止任务；
- 所有块完成后流式计算 staging 文件 SHA-256，与 offer 摘要一致才允许原子发布；不一致返回 `FILE_INTEGRITY_FAILED` 并清理 staging。

HTTP bearer token 仍为短期一次会话授权，但不承担内容机密性；分块密文认证才是内容安全边界。

## 暂停、续传与恢复

任务增加 `paused`、`reconnecting`、`verifying` 和 `recoverable` 状态。发送方通过加密控制消息查询接收方 verified bitmap，仅上传缺失块。bitmap 使用有界区间编码，必须与文件块数匹配，禁止无界数组。

- 用户暂停：双方保留任务和 staging，停止新 HTTP 请求；
- 网络断开：任务进入 `reconnecting`，在有界时间内只允许重连同一已认证身份；
- 重连成功：重新协商会话密钥，查询缺失块并继续；旧密钥、token 和密文不能复用；
- 超过恢复期限：任务进入 `recoverable`，等待用户手动继续或取消；
- 应用重启：从加密 task store 读取非终态任务，重新验证路径和源文件后展示“可恢复”；不会自动连接或自动发送；
- 用户继续：连接同一可信设备、重新批准恢复、建立新会话并上传缺失块；
- 用户取消：删除 task record、授权和 staging；已发布文件不回滚。

默认恢复记录保留 7 天，staging 与记录必须同时满足合法 ownership marker 才可恢复或清理。恢复记录达到上限时只淘汰最旧的非活动记录并安全清理对应 staging。

## 存储与 IPC

新增逻辑 store：

- `identity`：加密长期私钥、公开公钥、指纹和格式版本；
- `trusted-devices`：deviceId、公开公钥、指纹、首次/最后配对时间；
- `recoverable-transfers`：加密路径、文件身份、摘要、分块 bitmap、对端 deviceId、状态和过期时间。

renderer 只接收公开指纹、验证码、可信状态、任务进度和缺失块数量。IPC 只增加具名操作：配对确认/拒绝、列出/撤销可信设备、暂停、继续和取消恢复任务。IPC 不接受私钥、会话密钥、任意路径、任意文件内容或 renderer 构造的 bitmap。

## 错误码

协议 v3 新增稳定错误码：

```text
PAIRING_REQUIRED
PAIRING_REJECTED
PAIRING_TIMEOUT
IDENTITY_MISMATCH
SIGNATURE_INVALID
ENCRYPTION_FAILED
DECRYPTION_FAILED
MESSAGE_REPLAYED
FILE_HASH_FAILED
FILE_INTEGRITY_FAILED
CHUNK_INVALID
RESUME_STATE_INVALID
RESUME_EXPIRED
SOURCE_FILE_CHANGED
```

网络只传错误码和必要的非敏感上下文；中文提示与恢复建议仍在本地映射。

## 分阶段路线

0. 本文档、需求边界、威胁模型、协议 v3、存储迁移和发布门禁；
1. shared 协议 v3、配对/加密/分块 DTO、状态、错误码、常量和 schema；
2. 本机 Ed25519 身份、`safeStorage` 私钥保护、可信设备 store 和迁移；
3. X25519 配对握手、六位验证码、可信设备管理和审批 UI；
4. WebSocket transcript 认证、方向密钥、AEAD envelope、序号和重放防护；
5. 发送前流式 SHA-256、offer 摘要和接收后完整性校验；
6. HTTP 固定分块加密上传、bitmap、幂等块和安全发布；
7. 暂停/继续、断线重连、新会话续传和过期策略；
8. 加密恢复任务 store、重启恢复、源文件复核和 staging 生命周期；
9. 任务/配对/可信设备 UI、诊断脱敏、安全限流和攻击测试；
10. 版本 `0.4.0`、迁移回归、Windows/macOS 候选包和真实双平台签字。

每阶段独立执行 `pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm test` 和 `pnpm build`，完成后单独提交并推送。阶段 10 前不得宣称端到端加密、断点续传或双平台实机验收已完成。

## 当前实施状态

阶段 0 已完成需求边界、威胁模型、协议、存储和发布门禁规划。阶段 1 已完成独立协议 v3 shared 契约。阶段 2 已完成 Ed25519 长期身份、`safeStorage` 私钥保护、启动一致性校验和独立可信设备 store。阶段 3 已完成 X25519 临时密钥、规范 transcript、confirmation key、六位验证码、双端确认状态机、窄 IPC、配对确认框和可信设备取消信任界面；renderer 不取得身份公钥。密钥故障、拒绝、超时与身份冲突均失败关闭。运行时仍保持协议 v2，阶段 4 将 transcript 签名认证与 AEAD 原子接入后才启用 v3。

## 发布门禁

- 首次配对主动中间人模拟必须因验证码不一致被用户识别并拒绝；
- 已信任设备签名错误、deviceId 公钥变化、协议降级和消息重放必须失败关闭；
- 抓包不得出现文字、文件名、文件内容、完整摘要之外的敏感业务字段明文；
- 任意密文位翻转、tag 错误、块索引替换、跨文件重放和最终 SHA-256 不一致不得发布文件；
- 暂停、断网、服务重启、应用退出和系统重启后只能继续缺失块；
- 源文件变化、接收目录失效、staging 缺失或恢复记录损坏必须安全失败；
- Windows/macOS 双向覆盖 0 B、4 MiB 边界、跨多块大文件、多文件、文件夹、同名、中文、空格和括号；
- 诊断报告和日志不得包含验证码、长期/临时公钥原文、密钥、密文、完整摘要、bitmap、路径或文件名；
- Windows DPAPI/macOS Keychain 不可用时不得以明文私钥降级，应显示明确阻塞错误。
